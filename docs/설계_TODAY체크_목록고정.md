# 설계: TODAY 체크 시 목록 고정 (스냅샷 정렬) — 2026-08-08 확정

> 상태: ✅ **v2.5b에서 구현 완료** (2026-08-10 확인).
> 이 문서는 당시 설계 판단의 근거를 남긴 기록이며, 새로 할 작업은 없습니다.
> 구현 내용: TODAY 체크 시 목록이 흔들리지 않도록 정렬 스냅샷 고정
> 배경: v2.5a 사용 중 "당일 공사 TODAY 체크하자마자 목록이 변해서 헷갈린다" 제보.

---

## 1. 문제

TODAY 배지를 눌러 체크하는 순간, 목록이 즉시 재정렬되거나 카드 펼침이 바뀌어
화면이 출렁인다. 방금 누른 카드가 어디로 갔는지 눈이 따라가기 힘들다.

### 원인
- `displayItems`(정렬 결과)가 `useMemo`로 걸려 있고, 의존성에 `filteredItems`가 있음
  → 체크로 `items`가 바뀌면 **즉시 재정렬**됨 (index.html 1099~1108, deps: filteredItems·bookmarkIds·selectedDate)
- 카드 펼침(`isCardOpen`)도 `activeMark`/상태 변화에 즉시 반응 → 접힘/펼침이 실시간으로 바뀜
- 배지 색은 `isTodayActive`(todayOn), 정렬은 `hasWorkOn`(엑셀 배정)이라 기준이 달라
  체감상 더 혼란스러움

---

## 2. 원하는 동작 (실장님 확정)

**정렬은 "목록을 불러온 순간"에 한 번만 계산해 고정(스냅샷)한다.
그 뒤 체크질은 화면 순서·펼침을 건드리지 않는다.**

| 상황 | 체크하는 순간 | 다음 새로고침 때 |
|---|---|---|
| A. 이미 상위(오늘 인원 있음) 카드 체크 | 그대로 | 그대로 |
| B. 하위(오늘 인원 없음) 카드 체크 | **제자리(안 올라옴)** | 정리되어 위로 이동 |

→ 공통 원칙: **체크하는 순간에는 목록이 절대 안 움직인다. 색깔만 회색↔파랑.**

### "다음 새로고침" = 재정렬이 일어나는 시점 (실장님 확정)
- 앱을 다시 열 때
- 목록을 새로 불러올 때 (세션 로드, realtime 수신 등 items를 새로 받는 시점)

그 외(탭 이동, 06시 리셋, 수동 버튼)는 트리거로 삼지 않음.

---

## 3. 구현 방향 (착수 시)

핵심: 정렬 결과를 **매번 실시간 재계산하지 말고, "정렬된 id 순서"를 상태로 따로 잡아
불러온 시점에만 갱신**한다.

개략:
1. `sortedOrder`(정렬된 item id 배열) 같은 상태를 신설
2. 목록을 새로 불러오는 시점(초기 로드 useEffect, handleChangeSession/세션이동,
   realtime onUpdate 등 items를 새로 setItems 하는 곳)에서만 정렬 계산 → `sortedOrder` 갱신
3. 화면에는 현재 `items`를 `sortedOrder` 기준으로 배열해 표시.
   `sortedOrder`에 없는 새 항목(당일 추가 등)은 뒤에 붙이거나 그 시점 규칙대로 배치
4. 카드 펼침도 체크 순간엔 안 바뀌게: 배지 토글이 `isCardOpen` 판정을 즉시 흔들지 않도록
   펼침 스냅샷도 함께 고려 (접힘/펼침이 체크로 튀지 않게)

### 주의 (착수 시 반드시 확인) — 2026-08-08 확정됨
- **당일 공사 추가(긴급공사)**: 새로 추가된 항목은 **엑셀 기준 원래 순서 자리에** 배치
  (별도로 맨 위로 띄우지 않음). 즉 스냅샷 정렬 규칙(TODAY→즐겨찾기→공정→엑셀순서)을
  그대로 따르되, 반영은 다음 새로고침 시점에
- **realtime 수신**: 다른 사람의 수정도 **가져오되(데이터는 최신으로 갱신)**, 화면 순서
  재정렬은 **앱 재실행·목록 새로고침 시점에만** 반영. 즉 남이 수정해도 내가 보는 중인
  목록 순서는 그 자리에서 튀지 않고, 내가 새로고침할 때 정리됨
- **날짜 네비게이터**: 다른 날짜 보면 그 날짜 기준 재정렬 필요 (selectedDate 변화는 트리거)
- 기존 v2.5a 정렬 기준(TODAY→즐겨찾기→공정→엑셀순서)은 그대로. **언제 계산하느냐만 바꿈**

## 4. 버전·리스크
- 화면 표시 로직 변경(데이터 구조 불변). 버그 수정+동작 개선 성격 → 알파벳 접미사 후보(v2.5b)
- 리스크: 낮음~중간. 정렬 시점을 바꾸는 것이라, 트리거를 하나라도 빠뜨리면
  "새로고침해도 정리가 안 되는" 반대 문제가 날 수 있음 → 위 트리거 목록 전수 반영 필요
- 롤백: `sortedOrder` 상태를 걷어내고 useMemo 실시간 계산으로 되돌리면 즉시 복구
