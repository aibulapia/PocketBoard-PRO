## 1. 원문 기록 (제공받은 그대로)

### 목적
주말공사 웹앱에서 지금까지 나온 작업내용, 기능, 디자인, 운영 규칙을 한 번에 보는 백로그 정리본.

### 범위
- 공사 현장 작업 기록 정리
- 주말 공사 조회 및 엑셀 정리 규칙
- 웹앱 기능 구성
- 로그인 및 인증
- 화면/데이터 구조
- 배포와 운영 상태

### 현재 상태
- Supabase 프로젝트 생성 완료
- Netlify 배포 초안 완료
- Google 로그인 설정 완료
- Kakao 로그인 설정 완료
- index.html 초기 배포 완료
- 현재 배포본에는 로그인 관련 완성 코드가 누락된 상태

### 완료된 작업
- Supabase 프로젝트 생성 및 URL, 키 확인
- Supabase Site URL과 Redirect URL 등록
- Google OAuth 클라이언트 생성 및 설정
- Google OAuth 승인된 JavaScript 원본 등록
- Google OAuth 승인된 리디렉션 URI 등록
- Supabase Google Provider 활성화
- Supabase Kakao Provider 활성화
- index.html의 SUPABASE_KEY를 Legacy anon key로 교체
- loginWithgoogle, loginWithkakao 함수에 redirectTo 추가
- Netlify에 index.html 초기 배포

### 남은 작업
- 완성된 index.html을 Netlify Production에 재배포
- Supabase DB 테이블 생성 확인
- Google OAuth 동의 화면 게시 상태 확인
- 로그인 버튼 동작 확인
- 사진 업로드와 저장 흐름 점검
- 현장 메모 저장과 조회 흐름 점검
- 권한과 RLS 정책 점검

### 기능 백로그

**인증** — Google 로그인 / Kakao 로그인 / 로그인 후 사용자 프로필 연결

**프로젝트** — 공장 또는 현장명 등록 / 위치 등록 / 생성자 기록 / 현장 목록 조회

**작업보고** — 현장 메모 입력 / 사진 여러 장 업로드 / 사진 공개 URL 저장 / 작업별 보고서 목록 조회 / 날짜순 정렬

**데이터 관리** — profiles 테이블 / projects 테이블 / reports 테이블 / Storage 버킷 photos / 프로젝트별 폴더 경로 저장

**조회와 검색** — 프로젝트별 보고서 검색 / 작성자별 기록 조회 / 날짜별 필터 / 사진 포함 보고서 확인

**운영** — 배포본 확인 / 로그인 오류 점검 / 환경변수 또는 키 관리 / RLS 정책 검증

### 디자인 백로그
모바일 우선 레이아웃 / 상단 로그인 상태 표시 / 프로젝트 선택 영역 / 작업 메모 입력 영역 /
사진 첨부 버튼 / 등록 완료 피드백 / 목록 카드형 표시 / 상태 표시 배지 / 에러 메시지 영역

### 데이터 구조

| 테이블 | 컬럼 |
|---|---|
| profiles | id uuid, name text, role text |
| projects | id uuid, name text, location text, created_by uuid, created_at timestamp |
| reports | id uuid, project_id uuid, user_id uuid, memo text, photos text[], created_at timestamp |

### 스토리지 규칙
- 버킷명 `photos`
- 경로 `{project_id}/{timestamp}_{filename}`
- 접근 public

### 화면 흐름
로그인 → 프로젝트 선택 → 작업 메모 작성 → 사진 첨부 → 저장 완료 → 목록 확인

### 우선순위
로그인 동작 복구 → 테이블 생성 확인 → 보고서 저장 동작 확인 → 사진 업로드 확인 →
목록 조회 확인 → 화면 정리와 디자인 보완

### 검증 항목
Google 로그인 버튼 동작 / Kakao 로그인 버튼 동작 / reports 저장 / photos 버킷 업로드 /
프로젝트별 목록 표시 / 모바일 화면 버튼 터치

### 메모
주말공사는 현장 사진과 메모를 팀과 함께 기록하는 웹앱이며,
Supabase와 Netlify 기반으로 단순하게 유지하는 방향.

## 2. 포켓보드 PRO v2.22H와 대조

| 항목 | 주말공사 앱 | 포켓보드 PRO v2.22H | 판정 |
|---|---|---|---|
| 호스팅 | Netlify | Cloudflare Pages (`pocketboardprov2.pages.dev`) | 다름 |
| 백엔드 | Supabase (별도 프로젝트) | Supabase `pocketboard1` (ap-northeast-2) | 다름 (프로젝트 별개) |
| 로그인 | Google + Kakao OAuth (설정 완료, 코드 미배포) | **OAuth 없음.** 공사코드 + 관리자코드 2단계(RPC `master_level`) | 포켓보드 백로그 A안과 직결 |
| 사용자 계정 | profiles 테이블 (id/name/role) | 계정 개념 없음. 기기별 난수 ID(접속집계용)만 | 포켓보드에 없는 영역 |
| 현장 단위 | projects 테이블 (현장명/위치/생성자) | `session_registry` + 공사코드 = 세션 | 개념 유사, 구조 다름 |
| 작업 기록 | reports 테이블 (행 단위) | `pocket_sessions.items` **JSON 통째 저장** | 구조 크게 다름 |
| 사진 업로드 | Storage 버킷 `photos`, 다중 업로드 | **없음** | 신규 기능 후보 |
| 메모 | reports.memo | 카드별 메모 입력 있음 | 이미 있음 |
| 검색·필터 | 프로젝트별/작성자별/날짜별 | 날짜 네비(◀▶), 공장 탭, 즐겨찾기, 엑셀 내보내기 | 포켓보드가 더 진행됨 |
| RLS | "점검 필요" 단계 | `supabase-rls-v2.sql` 적용 완료 (DELETE 차단, 세션ID 6자 이상, 1MB 제한) | 포켓보드가 앞섬 |
| 모바일 UI | "모바일 우선 레이아웃" 계획 | PWA, 다크모드, 폴드4 폭 대응, 카톡 인앱 우회 완료 | 포켓보드가 크게 앞섬 |
| 엑셀 | "엑셀 정리 규칙" 언급 | 업로드 파싱 + 다운로드 + 구글시트 일일 백업 | 포켓보드가 앞섬 |
| 기상 정보 | 없음 | 기상청 API 실황·특보 연동 | 포켓보드만 있음 |
| 안전보고문 | 없음 | 폭염대책 자동 작성 + 카톡 복사 | 포켓보드만 있음 |

### 대조 결론

1. **대부분 항목은 포켓보드가 이미 더 앞서 있음.** 주말공사 앱의 기능 백로그 중
   메모·목록·검색·모바일 UI·RLS는 포켓보드에서 이미 운영 중.
2. **포켓보드에 없는 것은 딱 두 가지** — ① OAuth 로그인, ② 사진 업로드.
3. **데이터 구조 철학이 다름.** 주말공사는 행 단위(reports), 포켓보드는 세션 하나에
   JSON 통째. 두 앱을 합치려면 구조를 한쪽으로 통일해야 하므로 사실상 재작성 수준.

### 포켓보드로 가져올 만한 것 (검토용, 미확정)

| 후보 | 가치 | 걸림돌 |
|---|---|---|
| Google/Kakao 로그인 | 백로그 A안 그대로. **OAuth 설정을 이미 한 번 해본 경험**이 자산 | 현장 52명이 지금은 코드만 입력하면 끝. 로그인 강제는 진입 장벽이 됨 |
| 사진 업로드 | 점검 증빙 남기기에 유용 | Supabase 무료 용량·트래픽 한도. 공개 버킷이면 사진이 URL로 외부 노출됨 |
| 작성자별 기록 조회 | 감독자별 실적 확인 | 계정 체계가 있어야 성립 → 로그인 선행 필요 |
