## 1. 가장 심각했던 문제 — 삭제와 병합의 충돌

### 증상
공사 최종일이 지난 카드를 하나씩 지우는 로직(v2.19~v2.5f)과,
저장할 때 서버 것과 카드별로 합치는 로직(v2.5d)이 서로 충돌했다.

병합은 "고친 것"만 표현할 수 있고 **"없앤 것"은 표현할 수단이 없다.**
그래서 지운 카드가 서버에서 그대로 되살아났다.

```
지움(107→4) → 저장 → 서버와 병합 → 다시 107 → 지움 → 저장 → …  (무한 반복)
```

### 실제 데이터 시뮬레이션 (서버 백업본 `bak-default-20260808`, 107건)

| 라운드 | 화면 목록 | 만료 삭제 후 | 서버 병합 결과 |
|---|---|---|---|
| 1 | 107건 | 4건 | 107건 |
| 2 | 107건 | 4건 | 107건 |
| … | 멈추지 않음 | | |

- 실제 구성: 종료일 `2026-08-09` 103건 + 종료일 없는 긴급공사 4건
- 점검일(8/10) 기준으로 103건 전부가 만료 → 반복 조건 성립

### 2차 위험 — 데이터 전멸
이 반복 중 **서버 조회가 한 번만 실패하면** 병합을 포기하고 내 목록(4건)을 통째로 올린다.
→ 103건이 서버에서 영구 삭제. 시뮬레이션에서 `107건 → 4건` 확인.

### 실제 서버 상태 (점검일 조회)

| 세션 | 건수 | 비고 |
|---|---|---|
| **default (실사용)** | **0건** | 2026-08-10 04:17 UTC 갱신 |
| bak-default-20260808 | 107건 | 백업본 — 보존됨 |
| 옛 세션 8개 | 58~125건 | 미사용 잔여 |

### 조치 (v2.5g)
- 카드별 개별 삭제 → **시즌 전체 종료 시 일괄 삭제**
- 저장 직전에도 같은 규칙 재적용 (`setPostMergeFilter`) → 부활 차단
- 자세한 내용은 `CLAUDE.md`의 "데이터 구조상 반드시 기억할 함정" 참고

## 3. 보안 — 이전 점검 대비 변화 없음

서버를 직접 조회해 대조한 결과.

| 항목 | 상태 |
|---|---|
| S-1 마스터 코드 4자리 평문 | ❌ 그대로 (검증 함수가 4글자 2개를 평문 비교, 암호화 없음) |
| S-2 백업 토큰 | ⚠️ 서버 값은 이미 교체됨. **저장소 `.gs` 파일은 옛 값** → 재배포 시 백업 즉시 실패 |
| S-3 `pocket_sessions` RLS | ❌ 그대로 (정책 2개 모두 `무조건 허용`). README의 "완료됨" 표기는 오류 → v2.5g에서 정정 |

### 신규 발견
- **옛 세션 이름이 관리자 코드를 노출**: 공개 테이블에 `0909`, `mmeecsafe` 등이 남아 있어
  무차별 대입 없이도 코드 후보를 알 수 있다. → 옛 세션 삭제 필요 (BACKLOG B-4)
- **`config.js`의 키가 웹에 공개**: 구글시트 토큰(가짜 체감온도 기록 삽입 가능),
  기상청 키(사용량 소진). 저장소가 Private인 것과 무관하다.
- **앱스스크립트 기상청 중계에 암호 검사 없음**
