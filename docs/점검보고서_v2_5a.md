# 포켓보드 PRO 전면 점검 보고서

> 점검일: 2026-08-08 · 대상: v2.5a · 범위: 전체 파일(배포·서버·문서) 라인 점검
> 방식: 소스 라인 검토 + **실제 접속 주소·공개키로 공격 재현 테스트**

## 🔴 심각 (즉시 조치 권장)

### S-1. 마스터 코드가 서버에 평문으로 있고, 공개키로 무차별 대입 가능

**무슨 문제인가 (쉽게)**
누구든 앱 주소를 열고 소스 보기를 하면 `config.js`에서 서버 주소와 "공개 열쇠"를 얻습니다.
이 열쇠로 서버에 "이 코드 맞아?"를 **무한정 물어볼 수 있고**, 서버는 순순히 답합니다.
마스터 코드가 4자리 숫자(예: `2046`)라 0000~9999 전부 자동으로 시도하면
**수 분 안에 관리자·최고관리자 코드가 뚫립니다.**

**실제로 재현됨** (이번 점검에서 직접 확인)
```
코드 '0909' → 레벨 1 (일반 관리자)   ← 서버가 그대로 알려줌
코드 '2046' → 레벨 2 (최고 관리자)
코드 '1234' → 레벨 0 (틀림)
```
- 코드를 알아낸 뒤 곧바로 `master_list_contacts` 호출 → **직원 연락처 121건이 그대로 빠져나옴**
  (이번 점검에서 마스킹 처리해 유출 가능함을 실증)

**근본 원인**
- `master_level` 함수가 코드를 평문 `if p_code = '2046'`로 비교
- 호출 횟수 제한(rate limit)이 없어 무한 대입 가능
- 코드가 4자리 숫자라 경우의 수가 1만 개뿐

**조치 방향 (택1 또는 조합)**
1. **코드를 길고 복잡하게** — 4자리 숫자 → 최소 10자리 이상 영문+숫자.
   경우의 수가 폭발적으로 커져 무차별 대입이 사실상 불가능해짐 (가장 빠른 대응)
2. **시도 횟수 제한** — 같은 기기가 짧은 시간에 여러 번 틀리면 잠금 (서버 함수 개조 필요)
3. 코드도 해시로 저장 (지금 초기화 암호처럼) — 유출 시 원문 노출 방지

> 우선순위: **1번(코드 강화)을 오늘 바로**, 2·3번은 다음 단계.

### S-2. 백업 토큰도 평문, 앱스스크립트에 노출

- `backup_export('현재 토큰값')` 한 번이면 **등록된 전체 세션의 모든 공사
  데이터**가 쏟아져 나옴
- 이 토큰은 `apps-script-v3.gs`(server 폴더, 비공개)에만 있어 지금 당장 유출은 아니지만,
  **평문이고 절대 안 바뀌는 고정값**이라 한 번 새면 영구 위험
- **조치**: S-1 코드 교체할 때 이 토큰도 함께 길고 복잡하게 교체. SQL과 앱스스크립트
  양쪽을 같은 값으로 맞춰야 함

### S-3. 공사 데이터 테이블(pocket_sessions)이 완전 개방

**실제 DB 상태** (이번 점검에서 확인)
```
정책: pocket_sessions_public_all  →  qual: true (무조건 허용)
정책: allow all                   →  qual: true (무조건 허용)
```
- 공개키만으로 **누구나 모든 세션의 공사 데이터를 읽고·쓰고·지울 수 있음**
- 세션 코드(`5p`, `default` 등)만 알면 그 현장 데이터를 통째로 조작 가능
- `server/supabase-rls-v2.sql`에 **세션 코드 길이 검증 등 강화 정책이 준비돼 있으나,
  실제 DB에는 적용되지 않은 상태**

**조치**: `supabase-rls-v2.sql`을 실제로 실행. 단, 이 스크립트가 현재 쓰는 짧은 세션 코드
(`5p` 등 2자)와 충돌하지 않는지 먼저 확인 필요 (아래 주의)

## 🟡 중간 (기능·데이터 정합성)

### M-1. `todayOff` 필드 불일치 — 죽은 코드

- `storage.js` 168~186줄 병합 로직이 `todayOff` 필드를 보존하는데,
  **`index.html`에는 `todayOff`가 한 번도 안 쓰임** (실제로 쓰는 건 `todayOn`)
- 지금 당장 오류는 없지만, 병합 때마다 무의미한 필드가 계속 따라다님.
  과거 필드명이 바뀐 흔적으로 보임
- **조치**: `storage.js`의 `todayOff` 보존 줄 제거 (또는 `todayOn`으로 정정)

### M-2. `mergeItems` 감독자 덮어쓰기 (기존 확인된 사항)

- `assignedSupervisor: old.assignedSupervisor || p.assignedSupervisor` — 같은 시즌
  엑셀 재업로드 시 기존 입력이 새 엑셀 값보다 우선
- 실장님 워크플로우(새 시즌 = 초기화 먼저)에서는 문제 없음. **현행 유지 결정됨**,
  기록만 남김

### M-3. 자동 백업이 비어있는 등록소에 의존 (기존 확인된 사항)

- `session_registry`가 비어 있으면 매일 06시 백업이 아무것도 안 함.
  BACKLOG 검토항목 D로 보류 중 — 데이터 유실과 직결되므로 재확인 권장

## 🟢 양호 (문제 없음 확인)

- **개인정보(전화번호)**: `data.js`·`index.html` 등 공개 파일에 전화번호 하드코딩 **없음**
  (직급만 있음). 연락처는 서버에만 존재 — 원칙대로 지켜짐
- **초기화·회사명 암호**: SHA-256 해시로만 존재, 원문 노출 안 됨
- **XSS**: `dangerouslySetInnerHTML`·`eval`·`new Function` **하나도 없음**
- **React key**: `.map` 45곳 전수 확인, key 누락 **없음**
- **연락처 직접 조회**: `supervisor_contacts` 테이블은 RLS on + 정책 0개라 직접 조회 차단
  (단, S-1 경로로 RPC 우회 가능 — S-1이 해결되면 이 방어가 유효해짐)
- **보안 헤더**: `_headers`에 X-Frame-Options, nosniff, Referrer-Policy 등 적용됨
- **느슨한 비교(`==`)**: 발견된 건 전부 `== null`(null/undefined 동시 처리) 의도적 패턴
