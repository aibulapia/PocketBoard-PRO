## v2.52 (2026-08-11)

### 🐛 버그 수정 — 홈화면 아이콘(PWA)에서 "사이트에 연결할 수 없음 ERR_FAILED"가 계속 뜨던 문제
- **문제**: 캐시도 없고 네트워크도 실패하는 특정 상황에서 서비스워커(`sw.js`)가 처리 안 된
  오류를 그대로 던지면서 크롬이 자체 "ERR_FAILED" 화면을 띄움. 한 번 이 상태가 되면
  홈화면 아이콘을 지우고 앱 데이터를 삭제한 뒤 재설치해도 **같은 코드가 또 같은 방식으로
  실패**해서 계속 반복됨(안드로이드 WebAPK는 크롬 일반 탭과 별도 저장공간을 쓰기 때문에
  일반적인 "캐시 삭제"로는 안 풀림)
- **수정**: `sw.js`의 fetch 처리 로직 전체를 예외 안전(defensive)하게 재작성.
  캐시 조회·네트워크 요청 어느 단계에서 오류가 나도 절대 그냥 던지지 않고, 최소한 안내
  화면이라도 반환하도록 변경 — 브라우저의 ERR_FAILED 대신 앱 안에서
  "일시적으로 연결할 수 없습니다, 새로고침 해주세요" 화면이 뜸
- **추가 수정**: fallback 화면을 모듈 최상단에 `Response` 객체 하나로 만들어두고
  재사용하던 것을 `makeFallback()` 함수로 변경. `Response`는 body를 한 번 읽으면
  재사용할 수 없어, 같은 객체를 두 번째 요청에 반환하면 서비스워커 자체가 오류를 내고
  결국 같은 ERR_FAILED가 재발함
- 이 수정 이후에는 같은 문제가 재발해도 새로고침 한 번으로 복구 가능

- **증상**: 앱을 다시 켜면 즐겨찾기(★)가 저절로 해제됨
- **원인**: v2.23에서 즐겨찾기 기능을 만들 때 넣은 "없어진 공사의 즐겨찾기 자동 정리"
  로직에 방어 장치가 없었음. `items`(공사 목록)는 앱 시작 시 빈 배열로 출발하는데,
  서버에서 목록을 받아오기 **전**에도 이 정리 로직이 실행되어 "즐겨찾기한 공사가
  전부 사라졌다"고 오판하고 지워버림. 공사기간·날짜 계산과는 무관한 **로딩 순서 문제**
- **왜 v2.23에선 잘 되는 것처럼 보였나**: 타이밍에 따라 갈리는 문제라 기기·네트워크
  상태에 따라 나타나기도 하고 안 나타나기도 했음. v2.23에서도 잠재해 있던 버그
- **수정**: 정리 로직에 가드 3중 적용
  1. 로딩이 끝나기 전(`isLoading`)에는 실행하지 않음
  2. 목록이 비어 있으면(`items.length === 0`) 실행하지 않음
     — 네트워크 실패로 목록을 못 받아온 경우에도 즐겨찾기가 보존됨
  3. 즐겨찾기가 없으면 실행하지 않음
- 위 2번 가드로 인해 "전체 초기화" 시에는 자동 정리가 걸리지 않으므로,
  `doReset()`에서 즐겨찾기를 **직접 삭제**하도록 함께 보완

8월 하계공사(8/1~8/9, 9일치) 대응 중 발견된 날짜 처리 버그를 수정했습니다.
**기존 저장 데이터는 옛 구조이므로, 배포 후 초기화 → 엑셀 재업로드가 필요합니다.**

### 버그 수정

- **9일 이상 기간에서 같은 요일 데이터 소실**
  `dateWorkers` 키가 요일(0~6)이라 8/1(토)이 8/8(토)에, 8/2(일)이 8/9(일)에 덮어써져
  해당 날짜 공사가 목록에서 사라졌습니다. 키가 차 있으면 `+7`씩 밀어 저장하도록 변경.
- **TODAY 배지가 실제 날짜를 무시**
  요일만 대조해, 7월에 8월 공사표의 같은 요일 인원이 잡히며 오늘 작업이 없는데도
  배지가 떴습니다(7/27에 8/3 데이터로 오배지). `findDayWorkers`/`workersOn` 헬퍼를
  신설해 실제 날짜(+월)로 대조합니다.
- **오늘 조회 시 날짜 필터 미적용**
  오늘은 필터 없이 전체를 보여줘 8월 공사가 7월에도 전부 노출됐습니다.
  오늘 포함 모든 날짜에 필터를 적용하되, 진행 중 작업이 사라지지 않도록
  오늘 조회 중 **공사중**인 카드는 배정이 없어도 목록에 남깁니다.
- **등급 뱃지가 넓을 때 카드 뱃지 줄 깨짐**
  `P(A)급` 등에서 NO.가 아랫줄로 밀리고 공사전 뱃지가 세로로 찌그러졌습니다.
  우측 뱃지 그룹에 `flex-shrink-0` + `whitespace-nowrap` 적용, 좌측만 축소되도록 변경.
- **당일 공사 추가가 새 날짜 방식에서 동작 불가** (연쇄 영향)
  기존에는 `{day: 0}`으로 저장해 어떤 날짜와도 매칭되지 않았습니다.
  실제 날짜·월을 기록하도록 수정.

### 기능

- 공사목록 상단 `터치 시 기록/편집` 라벨 삭제
- `오늘 공사 N건 표시 중` 안내문을 항상 표시하고 글씨 확대
- 다른 날짜 조회 시 배지는 그 날짜 기준으로 표시(토글 비활성)

### 예방 조치

- 엑셀 파싱 시 **월(month) 정보를 함께 저장** (제목행에서 추출, 월말→월초 전환 감지)
- 종료일 계산도 저장된 월을 우선 사용해 월 추정 오판 방지
- 화면 표기는 기존과 동일 (`7/27(월)`)
- 구버전 데이터(월 정보 없음)는 **요일+날짜 동시 일치**로만 매칭 —
  다른 달의 같은 날짜가 잘못 잡히지 않도록 처리

### 검증

- 9/24~28, 10/3~5, 10/9~11 일정 정상
- 구버전 데이터(7/25~26) 호환 및 타월 오매칭 없음
