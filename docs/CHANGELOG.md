## v2.24c (2026-08-06)

### 관리자 모드 팝업이 30일 캐시 로그인을 못 알아보던 버그 수정
- **증상**: 관리자·최고관리자로 이미 30일 캐시 로그인돼 있어도, "🔑 관리자(마스터) 모드"
  팝업을 열면 매번 코드 입력 화면부터 다시 나옴. 그 안쪽에 있는 "인증 해제"(로그아웃)
  버튼에 사실상 도달하기 어려웠음
- **원인**: 인증 상태가 두 개로 나뉘어 있었음 — `masterLevel`/`adminAuthed`(30일 캐시,
  정상 복원)와 `masterAuthed`(팝업 전용 임시 상태, 항상 `false`로 시작 + 팝업 닫을 때마다
  리셋)가 서로 동기화되지 않음
- **수정**: `masterAuthed` 상태 제거, 이미 있는 `masterLevel > 0`(캐시 기반)으로 통일.
  관리자(레벨1)·최고관리자(레벨2) 공통 적용
- **검증**: 레벨 0/1/2 세 가지 상태로 렌더 테스트 — 로그인화면·인증해제버튼 노출 여부,
  버전 표시 문구까지 전부 기대값과 일치 확인

## v2.24b (2026-08-06)

### 여러 기기가 목록을 다시 불러올 때마다 체크·연장·TODAY가 되돌아가던 버그 수정
- **증상**: 공사를 "공사중"으로 체크해 저장했는데, 짧게는 1~20분, 길게는 그 이상 지난 뒤
  다시 열어보면 체크가 풀려 "공사전"으로 돌아가 있고, 연장시간·TODAY도 함께 초기화됨.
  하루에 여러 번 반복 발생. v2.23까지는 눈에 띄지 않다가 v2.24 전후로 두드러짐
- **원인**: 입력을 저장할 때 상태(`status`)는 오늘 걸로 바뀌지만, 그 항목이
  "마지막으로 06시 일일리셋 처리된 날"을 기록하는 `dayKey`는 갱신되지 않았음.
  이 앱은 여러 사람이 같은 공사 목록("default" 세션)을 함께 보는 구조라, 누군가의
  화면에서 목록이 다시 로드될 때마다 06시 자동 리셋 로직이 "이 항목은 dayKey가
  옛날이니 하루 지났다"고 오판 → 방금 저장한 체크·연장·TODAY를 도로 되돌리길 반복.
  실제로는 v2.5(06시 일일사이클 도입) 때부터 잠재했던 구조적 버그
- **참고**: ★ 즐겨찾기는 이 버그와 무관한 별개 저장 방식(v2.24a에서 이미 별도 수정)
- **수정**: 입력 저장 시(카드 체크·연장 설정 등) `dayKey`도 함께 오늘 날짜로 갱신,
  카드 입력 초기화 시에도 동일하게 일관성 유지

## v2.24a (2026-08-04)

### ⏰ 연장 보고 버튼 삭제
- v2.23에서 추가했던 마스터 전용 "⏰ 연장 보고" 일괄복사 버튼과 `handleExtensionReport`
  함수를 함께 제거 (사용하지 않기로 결정)

### 즐겨찾기가 앱 재실행 시 풀리던 버그 수정
- **증상**: 앱을 다시 켜면 즐겨찾기(★)가 저절로 해제됨
- **원인**: v2.23에서 즐겨찾기 기능을 만들 때 넣은 "없어진 공사의 즐겨찾기 자동 정리"
  로직에 방어 장치가 없었음. `items`(공사 목록)는 앱 시작 시 빈 배열로 출발하는데,
  서버에서 목록을 받아오기 **전**에도 이 정리 로직이 실행되어 "즐겨찾기한 공사가
  전부 사라졌다"고 오판하고 지워버림. 공사기간·날짜 계산과는 무관한 **로딩 순서 문제**
- **왜 v2.23에선 잘 되는 것처럼 보였나**: 타이밍에 따라 갈리는 문제라 기기·네트워크
  상태에 따라 나타나기도 하고 안 나타나기도 했음. v2.23에서도 잠재해 있던 버그
- **수정**: 정리 로직에 가드 3중 적용
  1. 로딩이 끝나기 전(`isLoading`)에는 실행하지 않음
  2. 목록이 비어 있으면(`items.length === 0`) 실행하지 않음
     — 네트워크 실패로 목록을 못 받아온 경우에도 즐겨찾기가 보존됨
  3. 즐겨찾기가 없으면 실행하지 않음
- 위 2번 가드로 인해 "전체 초기화" 시에는 자동 정리가 걸리지 않으므로,
  `doReset()`에서 즐겨찾기를 **직접 삭제**하도록 함께 보완

### 버그 수정

- **9일 이상 기간에서 같은 요일 데이터 소실**
  `dateWorkers` 키가 요일(0~6)이라 8/1(토)이 8/8(토)에, 8/2(일)이 8/9(일)에 덮어써져
  해당 날짜 공사가 목록에서 사라졌습니다. 키가 차 있으면 `+7`씩 밀어 저장하도록 변경.
- **TODAY 배지가 실제 날짜를 무시**
  요일만 대조해, 7월에 8월 공사표의 같은 요일 인원이 잡히며 오늘 작업이 없는데도
  배지가 떴습니다(7/27에 8/3 데이터로 오배지). `findDayWorkers`/`workersOn` 헬퍼를
  신설해 실제 날짜(+월)로 대조합니다.
- **오늘 조회 시 날짜 필터 미적용**
  오늘은 필터 없이 전체를 보여줘 8월 공사가 7월에도 전부 노출됐습니다.
  오늘 포함 모든 날짜에 필터를 적용하되, 진행 중 작업이 사라지지 않도록
  오늘 조회 중 **공사중**인 카드는 배정이 없어도 목록에 남깁니다.
- **등급 뱃지가 넓을 때 카드 뱃지 줄 깨짐**
  `P(A)급` 등에서 NO.가 아랫줄로 밀리고 공사전 뱃지가 세로로 찌그러졌습니다.
  우측 뱃지 그룹에 `flex-shrink-0` + `whitespace-nowrap` 적용, 좌측만 축소되도록 변경.
- **당일 공사 추가가 새 날짜 방식에서 동작 불가** (연쇄 영향)
  기존에는 `{day: 0}`으로 저장해 어떤 날짜와도 매칭되지 않았습니다.
  실제 날짜·월을 기록하도록 수정.
