01

개요

앱스토어에서 내려받지 않습니다. 주소만 열면 바로 쓰는 웹 앱입니다.

기존 방식의 문제포켓보드 PRO의 해결
공사 목록이 엑셀에만 있어 현장에서 열기 불편엑셀 한 번 올리면 전원 휴대폰에 카드로 표시
누가 어디까지 점검했는지 실시간 파악 불가체크하는 즉시 모든 사람 화면에 반영
안전보고문·카톡 보고문을 매번 손으로 작성입력 내용으로 자동 생성 후 복사
폭염 시 체감온도를 따로 계산기온·습도만 넣으면 계산 + 조치 문구 자동
기록이 개인 휴대폰에만 남고 사라짐서버 저장 + 매일 구글시트 자동 백업
12지원 공장
52감독자 (연락처 기준)
06:00하루의 시작
1h수정 후 전원 반영

설치가 필요 없다는 것의 의미

앱 심사·배포 절차가 없어 고치면 최대 1시간 안에 전 인원에게 반영됩니다. 안드로이드·아이폰 구분 없이 동일하게 동작하고, 카카오톡 링크로 열면 자동으로 정식 브라우저로 넘어갑니다. "홈 화면에 추가"를 하면 일반 앱처럼 아이콘이 생깁니다.

적용 범위

  • 공장 12개 — 1~5공장, 6.엔진, 7.변속기, 8.소재, 9.기타, 10.아산, 11.남양, 12.광명
  • 하위공장(부서)까지 등록된 곳은 9개 공장. 10.아산·11.남양·12.광명은 탭만 있고 하위공장·감독자 명단은 아직 비어 있음
  • 감독자 — 명단 49명(data.js) / 전화번호 52명(서버). 명단에 없는 협력사 감독자는 이름을 직접 입력해 사용
  • 주 사용 시점 — 주말·공휴일 공사, 하계·동계 집중 공사 기간
02

권한 3단계

아이디·비밀번호가 없습니다. 코드를 넣으면 그 기기의 권한이 30일간 올라갑니다.

감독자기본

주소만 열면 됨. 점검 기록, 체감온도 계산, 카톡 복사, 안전보고문 생성, 즐겨찾기, 긴급공사 추가

관리자레벨 1

위 전부 + 공지사항 작성, 감독자 연락처 조회·추가·전화 걸기

최고관리자레벨 2

위 전부 + 전체 초기화, 엑셀 파일 변경, 현장 등록소 관리, 전체 통합 엑셀, 연락처 삭제, 회사명 수정, 접속 현황 조회

이 구조의 장점과 한계

장점 — 40~50대 현장 감독자가 가입하거나 비밀번호를 외울 필요가 없습니다. 주소만 눌러도 바로 써서 도입 저항이 거의 없습니다.

한계 — 개인 계정이 없으므로 "누가 입력했는지"를 시스템이 자동으로 구분하지 못합니다. 대신 입력란의 "감독자" 항목에 이름을 적어 기록을 남깁니다.

비밀번호 보관 — 초기화·회사명 암호는 앱 소스에 되돌릴 수 없는 해시로만 저장됩니다. 관리자 코드는 아예 서버에서 검증하므로 휴대폰에서 소스를 열어봐도 알 수 없고, 실제 값은 저장소 어디에도 기록하지 않습니다.

06시 일일 사이클

이 앱의 심장. 하루는 06:00에 시작해 다음날 05:59에 끝납니다.

왜 자정이 아닌가

공사가 밤을 넘겨 새벽 2~3시까지 이어지는 일이 흔합니다. 자정을 기준으로 하루를 나누면 밤 12시가 지나는 순간 진행 중이던 공사가 "어제 것"이 되어 체크가 풀려버립니다. 새벽 3시에 일하고 있어도 여전히 "어제 시작한 그 하루"여야 합니다.

  • 06 – 17시 · 주간 작업점검 기록, 체감온도 측정, 카톡 보고가 이뤄지는 시간대
  • 17시 · 종료 판정이 시각을 넘기면 연장을 지정하지 않은 공사는 "종료"로 표시
  • 18 – 05시 · 연장 가능 구간−/+ 버튼으로 고를 수 있는 범위. 하루의 정확히 절반

06시에 자동으로 일어나는 일

공사기간 끝난 카드목록에서 완전 제거
앱을 켜둔 상태에서도 분 단위로 감지해 자동 전환됩니다. 06시에 앱을 다시 켤 필요가 없습니다.

이 사이클과 얽힌 사고 사례

06시 사이클은 앱 전체에서 가장 많은 버그의 원인이었습니다. 아래 두 건은 실제로 발생해 수정된 사례이며, 앞으로 코드를 고칠 사람이 반드시 알아야 할 내용입니다.

사례 1 — 체크가 저절로 풀리던 문제 v2.24b 수정

각 공사에는 "마지막으로 06시 처리를 한 날짜"가 함께 저장됩니다. 그런데 점검 기록을 저장할 때 상태만 바뀌고 이 날짜는 갱신되지 않았습니다. 여러 사람이 같은 목록을 함께 보는 구조라, 누군가의 화면에서 목록이 다시 불러와질 때마다 "이 공사는 날짜가 옛날이니 하루 지났다"고 잘못 판단해 방금 저장한 체크를 되돌렸습니다.

→ 저장할 때 날짜도 함께 오늘로 찍도록 수정. 실제로는 v2.0(06시 체계 도입) 때부터 잠재해 있던 구조적 문제였습니다.

사례 2 — 즐겨찾기가 앱 재실행 시 풀리던 문제 v2.24a 수정

"없어진 공사의 즐겨찾기를 자동 정리"하는 기능이 서버에서 목록을 받아오기 전에도 실행됐습니다. 그 순간 목록이 비어 있으니 "즐겨찾기한 공사가 전부 사라졌다"고 오판해 지워버렸습니다. → 목록을 다 받아온 뒤에만 정리가 돌도록 3중 안전장치 추가.

교훈

06시 사이클이나 자동 정리 로직을 건드릴 때는 "목록을 아직 못 받아온 상태"와 "방금 저장한 직후" 두 순간을 반드시 함께 검증해야 합니다.

파일 구성

폴더내용웹 공개
public/index.html, config.js, data.js, storage.js, manifest, 아이콘이것만 배포
server/Supabase SQL, 앱스스크립트비공개
docs/README, 백서, 변경이력, 백로그비공개

새 파일을 추가할 때 웹에 공개돼도 되는 것만 public/에 넣습니다. 과거에 감독자 연락처가 담긴 SQL 파일이 웹 주소로 접근 가능했던 사고가 있었고, 그때 이 3분할 구조가 만들어졌습니다.

기술적 특징

  • 단일 파일 구조 — 거의 모든 기능이 index.html 한 파일(약 3,400줄)에. 빌드 과정이 없어 수정·배포가 매우 빠름
  • 명단은 data.js로 분리 — 본체를 건드리지 않고 인사 변동에 대응
  • 캐시 1시간 — 배포 후 최대 1시간 내 자동 반영, 새로고침하면 즉시

보안 조치 이력 2026-07-26

저장소의 모든 파일이 웹에 배포되어, 관리자 코드와 감독자 52명 연락처가 담긴 SQL 파일이 인터넷 주소로 직접 접근 가능한 상태였습니다.

  • 저장소를 public/ · server/ · docs/로 3분할 → public/만 배포
  • 백업 문서를 인증정보 제거본으로 교체
  • 소스 주석에 남아 있던 관리자 코드 문자열 제거 — 주석도 소스보기로 노출됨
  • 관리자 코드·백업 토큰 전면 교체 (2026-07-27 완료), 새 값은 저장소에 기록하지 않음

개발 원칙

#원칙왜
1구버전 데이터 호환 필수이미 저장된 기록이 새 코드에서 깨지면 안 됨
2런타임 모호함은 안전한 쪽으로조회 실패 시 "잘못된 것 표시"보다 "기존 값 유지"
3엣지 케이스는 실제 파일로 검증코드만 보고 "될 것 같다"로 넘기지 않음
4한 곳 고치면 연쇄 영향 전수 조사같은 데이터를 쓰는 다른 곳까지 함께 확인
5완성 후 객관적 재검토 별도 수행"다 됐습니다"로 끝내지 않고 버그 관점 재점검
6요구사항 모호하면 선택지 제시임의 판단 금지
7설명은 쉽고 간결하게사용자는 개발자가 아닌 현장 안전 실무자
추가로, "코드 작성"이라는 지시가 나오기 전까지는 실제 코드를 건드리지 않습니다. "반영하자", "고치자" 같은 말은 방향 합의일 뿐 착수 신호가 아닙니다.

사양은 확정, 착수 지시 대기 중입니다.

오프라인 지원 다음 차례

지금은 인터넷이 끊기면 화면조차 뜨지 않습니다. 공장 지하나 밀폐 공간처럼 신호가 약한 곳에서 치명적입니다.

온라인 때오프라인에서
목록 조회마지막으로 받아둔 목록 그대로 표시
점검 입력완전히 동일하게 입력 가능
저장기기에 저장 + "오프라인 저장됨" 표시
—인터넷 복귀 시 자동으로 순서대로 전송

핵심 전제 — 공사 1개는 감독자 1명이 항상 전담하므로 기록이 충돌해 합쳐야 하는 상황이 없습니다. 복잡한 병합 없이 순서대로 다시 보내면 됩니다.

제약 — public/sw.js라는 새 파일이 반드시 필요합니다. 브라우저 규격상 index.html 안에 숨겨 넣을 수 없어(보안상 금지), 컴퓨터 작업이 가능할 때 착수합니다.

사진 촬영 + 구글 드라이브 백업 v2.26 예정

  • 권한 — 관리자(레벨1) 이상 / 방식 — 카메라 즉석 촬영만 (갤러리 선택 불가)
  • 저장 — 구글 드라이브에 공장별 폴더 자동 생성, 파일명 공사명_촬영일자_순번
  • 순번 중복 방지 — 여러 감독자가 같은 날 같은 공사를 찍어도 겹치지 않도록 서버가 저장 직전 기존 파일을 확인해 다음 번호를 매김
  • 열람 — 폴더 주인은 전체 열람, 감독자끼리는 서로 못 봄
  • 장수 제한 없음 — 10장 넘으면 안내 문구만 표시 (차단 아님)
