# 1. 개요 — 무엇을 하는 앱인가

## 1-1. 한 줄 요약

**주말·공휴일에 여러 공장에서 동시에 진행되는 공사를, 감독자들이 휴대폰 하나로 점검하고
보고할 수 있게 만든 현장 안전관리 앱**입니다.

## 1-2. 왜 만들었나

기존 방식에는 다음과 같은 어려움이 있었습니다.

| 기존 방식의 문제 | 포켓보드 PRO의 해결 |
|---|---|
| 공사 목록이 엑셀 파일로만 존재 → 현장에서 열어보기 불편 | 엑셀을 한 번 올리면 전원 휴대폰에 카드 형태로 표시 |
| 누가 어디까지 점검했는지 실시간 파악 불가 | 체크하는 즉시 모든 사람 화면에 반영 |
| 안전보고문·카톡 보고문을 매번 손으로 작성 | 입력한 내용으로 자동 생성 → 복사 |
| 폭염 시 체감온도를 따로 계산해야 함 | 기온·습도 입력하면 즉시 계산 + 단계별 조치 문구 자동 |
| 기록이 개인 휴대폰에만 남고 사라짐 | 서버 저장 + 매일 구글시트 자동 백업 |

## 1-3. 설치가 필요 없는 앱 (PWA)

앱스토어·플레이스토어에서 내려받지 않습니다. 인터넷 주소만 열면 바로 쓸 수 있고,
"홈 화면에 추가"를 하면 일반 앱처럼 아이콘이 생깁니다.

- 앱 심사·배포 절차가 없어 **수정하면 최대 1시간 안에 전원에게 반영**
- 안드로이드·아이폰 구분 없이 동일하게 동작
- 카카오톡 링크로 열면 자동으로 정식 브라우저(크롬·사파리)로 넘어감

## 1-4. 적용 범위

- **공장**: 12개 (1~5공장, 6.엔진, 7.변속기, 8.소재, 9.기타, 10.아산, 11.남양, 12.광명)
  - 하위공장(부서)까지 등록된 곳은 9개 공장
  - 10.아산 · 11.남양 · 12.광명은 **공장 탭만 있고 하위공장·감독자 명단은 아직 비어 있음**
- **감독자**: 명단 등록 49명(`data.js` 기준, 이화선 2·3공장 중복 제외) /
  전화번호 등록 52명(서버 기준)
  - 명단에 없는 협력사·직원 감독자는 **이름을 직접 입력**해 사용 (정상 동작)
- **주 사용 시점**: 주말·공휴일 공사, 하계·동계 집중 공사 기간

# 2. 사용 대상과 권한 3단계

## 2-1. 권한 구조

로그인 계정(아이디·비밀번호)이 따로 없습니다. **코드를 입력하면 그 기기의 권한이 올라가는 방식**이며,
한 번 인증하면 **30일간 유지**됩니다.

| 구분 | 진입 방법 | 할 수 있는 일 |
|---|---|---|
| **감독자** (기본) | 주소만 열면 됨 | 공사 점검 기록, 체감온도 계산, 카톡 복사, 안전보고문 생성, 즐겨찾기, 긴급공사 추가 |
| **관리자 (레벨1)** | 공사코드 칸 → 🔑 관리자 모드 → 일반 코드 | 위 전부 + 공지사항 작성, 감독자 연락처 조회·추가·전화 걸기 |
| **최고관리자 (레벨2)** | 같은 방법 → 최고 코드 | 위 전부 + 전체 초기화, 엑셀 파일 변경, 현장(세션) 등록소 관리, 전체 통합 엑셀, 연락처 삭제, 회사명 수정, 접속 현황 조회 |

## 2-2. 이 구조의 장점과 한계

**장점** — 40~50대 현장 감독자가 아이디·비밀번호를 외우거나 가입할 필요가 없습니다.
주소만 눌러도 바로 쓸 수 있어 도입 저항이 거의 없습니다.

**한계** — 개인별 계정이 없으므로 **"누가 입력했는지"를 시스템이 자동으로 구분하지 못합니다.**
대신 입력란의 "감독자" 항목에 이름을 적는 방식으로 기록을 남깁니다.
(향후 개인 식별이 필요해지면 구글 로그인 도입이 별도 과제로 남아 있습니다 — 9장 참고)

## 2-3. 비밀번호 보관 방식

- 초기화·회사명 수정 암호: 앱 소스 안에 **해시(암호를 되돌릴 수 없게 뭉갠 값)로만** 저장
- 관리자 코드: 앱이 아니라 **서버에서 검증** → 휴대폰에서 소스를 열어봐도 알 수 없음
- 실제 코드 값은 저장소(GitHub) 어디에도 기록하지 않고 별도 보관

# 3. 화면 구성

## 3-1. 상단 헤더 (4줄)

```
1줄  [MMEEC 로고]  포켓보드 PRO              ◑  📖  ❓
2줄  공사 코드  [default]          (레벨2만) 초기화 · 파일변경
3줄  🌤️  ◀ 8/6(목) ▶       오늘 공사 12건 표시 중        🏭 내 공장
4줄  [+ 공사추가] [전체] [1공장] [2공장] ... ← 좌우 스크롤
```

| 아이콘 | 위치 | 기능 |
|---|---|---|
| ◑ (반원) | 1줄 | 다크모드 켜기/끄기 |
| 📖 | 1줄 | 도움말 (화면별 FAQ 8개) |
| ❓ | 1줄 | 앱 정보 (목적·사용대상·버전·제작자) |
| 🌤️ | 3줄 | 기상 정보 팝업 (울산 양정동 기온·습도·특보) |
| 🏭 | 3줄 | 내 담당 공장 설정 |

> **로고 자리**는 최고관리자(레벨2)만 눌러서 회사명을 바꿀 수 있습니다.
> 그 외 사용자는 눌러도 아무 반응이 없습니다.
> **공사추가 버튼**은 탭과 달리 스크롤되지 않고 항상 맨 앞에 고정됩니다.

## 3-2. 공사 카드 목록

카드 하나가 공사 하나입니다. 접힌 상태에서는 제목만, 진행 중이거나 오늘 배정된 공사는
펼쳐진 상태로 표시됩니다.

카드에 표시되는 것:

- **NO.** / 등급 배지(P(A)급 등) / 공장 배지("전체" 탭에서만)
- **상태 배지** — 공사전 / 공사중 / 연장중 / 종료 / OO시연장
- **★** 즐겨찾기 표시
- **TODAY 배지** — 오늘 인원이 배정된 공사, 2일째부터 "TODAY 2일째"
- 체감온도 칩 (측정했다면)

> 목록은 공장·시간 순서를 그대로 유지하되, **즐겨찾기한 공사만 맨 위로** 올라옵니다.

## 3-3. 공사 세부 화면 (바텀시트)

카드를 터치하면 아래에서 올라오는 입력 화면입니다. 여기서 실제 점검 기록을 합니다.

**입력 항목**

| 항목 | 설명 |
|---|---|
| 공사위치 | 층수 탭(B1·1층·2층·2.5층·3층·옥상·옥외) 선택 또는 직접 입력 |
| 감독자 | 명단에서 선택 또는 직접 입력 |
| 인원 | 직영 / 일용 / 협력업체명+인원 |
| 65세 이상 고령자 | 여부 + 인원수 |
| 작업유형 | 고소·중량물·화기·밀폐·건설기계·전기·자동화·청소·운반·도색 (복수 선택) |
| 메모 | 자유 입력 |
| ⏰ 작업연장 | −/+ 버튼으로 18시~다음날 05시 선택 |
| 🌡️ 체감온도 | 기온·습도 입력 → 자동 계산 |
| 보고 단계 | 공사 전 / 중 / 후 |

**하단 버튼**: `💬 카톡복사` / `★ 즐겨찾기` / `입력 완료`

> **공사위치와 감독자를 모두 채우면** 그 공사가 자동으로 "공사중"으로 바뀝니다.
> 둘 중 하나라도 비면 "공사전" 상태로 남습니다.

# 4. 기능 총망라

## 4-1. 공사 목록 불러오기 (엑셀 업로드)

- **권한**: 최고관리자(레벨2)만 가능
- 하계공사 엑셀 파일을 그대로 올리면 자동으로 읽어 카드로 만듭니다
- 읽어내는 정보: 공사번호, 공장, 위치, 공사명, 업체, 감독자, 등급, **날짜별 배정 인원**
- 엑셀 제목행에서 **월(月) 정보까지 추출** → 월이 바뀌는 공사(7/31~8/9 등)도 정확히 처리
- 공사 최종일이 지난 카드는 06시에 **자동으로 목록에서 사라짐**

## 4-2. 점검 기록 (핵심 기능)

카드를 눌러 공사위치·감독자·인원 등을 입력하고 "입력 완료"를 누르면:

1. 상태가 **공사중**으로 바뀜
2. **TODAY 배지가 자동 활성화** (오늘 배정이 없던 공사면 1명으로 자동 배정)
3. 서버에 저장되어 **같은 공사코드를 쓰는 모든 사람 화면에 반영**

## 4-3. 체감온도 계산 + 폭염 대책

- **계산식**: 기상청 2022년 개정 산출식 (화면 표기는 "안전보건공단 KOSHA 공식")
- 기온·습도를 넣으면 체감온도가 **소수점 첫째 자리**까지 즉시 계산됩니다

| 단계 | 기준 | 색 | 조치 문구 |
|---|---|---|---|
| 보통 | 31℃ 미만 | 회색 | 쾌적한 작업 환경 |
| 관심 | 31℃ 이상 | 하늘 | 충분한 물 섭취, 주기적 휴식 |
| 주의 | 33℃ 이상 | 노랑 | 2시간 작업 시 20분 휴식 |
| 경고 | 35℃ 이상 | 주황 | 매시간 15분 휴식 권고 |
| 위험 | 38℃ 이상 | 빨강 | 작업 중지 권고, 즉시 대피 |

- 측정하면 **구글시트로 자동 전송**되어 기록이 남습니다
- 기록은 하루치만 화면에 보이고(06시 기준), 원본은 백업에 보존됩니다

## 4-4. 안전보고문 생성

버튼을 누르면 아래 형식의 문서가 자동으로 만들어지고, **편집 가능한 팝업**이 뜹니다.
내용을 고친 뒤 "클립보드 복사"를 누르면 됩니다.

```
공사 중 안전작업 이행결과
*업 체 명 : MMEEC
*허가번호 : 2607
*작업위치 : 2층 압축기실
*작업유형 : 고소작업, 화기작업
*작업내용 : OO설비 배관 교체
*작업연장 : 22시연장
*안전대책 :
  - (작업유형별 대책 자동 삽입)
  - (공통 안전수칙 자동 삽입)
*폭염대책 : 체감온도 33.4℃ (주의)
  - 2시간 작업 시 20분 휴식
*65세이상 고령자 : 65세 이상 작업자 없음
* TBM 실시 후 작업 시작합니다.
```

**단계별 차이**

| 단계 | 체감온도 기준 | 특징 |
|---|---|---|
| 공사 전 | 그날 **최초** 기록 | 안전대책 전체 포함 |
| 공사 중 | **12:00~14:00 사이 최초** 기록 | 안전대책 전체 포함 |
| 공사 후 | 없음 | 짧은 종료 문구로 대체 |

> **v2.24부터** 체감온도를 측정하지 않아도 보고문을 만들 수 있습니다.
> 기록이 있으면 폭염대책 줄이 들어가고, 없으면 그 줄만 빠집니다.

> 카드 목록의 단축 버튼은 **5공장에서만** 시범 운영 중입니다.
> 공사 세부 화면 안의 안전보고문 기능은 **전 공장 공통**으로 사용할 수 있습니다.

## 4-5. 카톡 복사

카톡방에 그대로 붙여넣을 수 있는 짧은 문구를 만들어 복사합니다.

```
OO설비 배관 교체  22시연장
  2층 압축기실  감독-홍길동
직3 일용2 OO산업 4
```

## 4-6. 작업연장

- 17시 이후에도 계속되는 공사의 **종료 예정 시각**을 기록합니다
- **−/+ 버튼**으로 한 시간씩 조절 (v2.24에서 개편)
- 범위: 18시 ~ 다음날 05시 / 18시에서 −를 누르면 "없음"으로 돌아감
- 카드 배지, 카톡 복사, 안전보고문에 **자동으로 함께 반영**

| 시점 | 연장 없음 | 연장 있음 |
|---|---|---|
| 17시 이전 | 공사중 (초록) | **연장중** (남색) |
| 17시 이후 | 종료 (회색) | **22시연장** (남색) |

## 4-7. 즐겨찾기 (★)

- 개수 제한 없이 여러 개 지정 가능
- ★를 다시 눌러야만 해제 (자동 해제 없음)
- 지정한 공사는 **목록 맨 위로** 모여 표시
- 공사기간이 끝나거나 전체 초기화하면 자동 정리

## 4-8. TODAY 배지 · n일째

- 오늘 인원이 배정된 공사에 파란 배지가 붙습니다
- 배지를 터치하면 **파랑 ↔ 회색(취소)** 전환 (오늘은 안 한다는 표시)
- **실제로 일한 날만** 세어 2일째부터 "TODAY 2일째"로 표시
- 취소한 날은 세지 않습니다

## 4-9. 긴급공사 추가

엑셀에 없던 공사가 갑자기 생겼을 때, 감독자가 직접 추가할 수 있습니다.

- 공장 → 하위공장 → 작업위치 → 작업내용 → 담당 감독자 → 작업유형 순서로 입력
- 공사명은 입력한 내용을 조합해 **자동 생성**
- 목록에 `긴급` 표시로 구분되어 나타남

## 4-10. 기상 정보 팝업 (🌤️)

- 울산 북구 양정동 기준 **실시간 기온·습도** (기상청 초단기실황)
- **기상특보 배지** — 중대경보(진한 빨강·깜빡임) → 경보(빨강) → 주의보(주황) 순 정렬
- 특보 통보문 원문도 펼쳐서 확인 가능
- 1시간마다 자동 갱신, 조회 실패 시 직전 정보 유지

## 4-11. 날짜 넘겨보기

# 5. 06시 일일 사이클 — 이 앱의 심장

## 5-1. 왜 자정이 아니라 06시인가

공사가 밤을 넘겨 새벽 2시, 3시까지 이어지는 일이 흔합니다.
자정을 기준으로 하루를 나누면, **밤 12시가 지나는 순간 진행 중이던 공사가
"어제 것"이 되어 체크가 풀려버립니다.**

그래서 이 앱은 **하루를 06:00 ~ 다음날 05:59로 정의**합니다.
새벽 3시에 일하고 있어도 여전히 "어제 시작한 그 하루"입니다.

## 5-2. 06시에 자동으로 일어나는 일

| 대상 | 처리 |
|---|---|
| 공사 상태 | 공사중 → **공사전(재확인)** 으로 되돌림 |
| 작업연장 | 초기화 |
| TODAY 배지 | 취소 상태 해제 (다시 활성으로 복귀 가능) |
| 작업일수 | 전날 TODAY가 켜져 있었다면 **"n일째" +1 확정** |
| 체감온도 | 화면에서는 숨김 (**데이터는 보존** — 백업·이력에 사용) |
| 공사기간 끝난 카드 | **목록에서 완전 제거** |

앱을 켜둔 상태에서도 분 단위로 감지해 자동 전환됩니다.
06시에 앱을 다시 켤 필요가 없습니다.

## 5-3. 주의 — 이 사이클과 얽힌 대표적 사고 사례

이 06시 사이클은 앱 전체에서 가장 많은 버그의 원인이 됐던 부분입니다.
아래 두 건은 실제로 발생해 수정된 사례이며, 앞으로 코드를 고칠 사람이
반드시 알아야 할 내용입니다.

**사례 1 — 체크가 저절로 풀리던 문제 (v2.24b에서 수정)**

각 공사에는 "마지막으로 06시 처리를 한 날짜"가 함께 저장됩니다.
그런데 점검 기록을 저장할 때 **상태만 바뀌고 이 날짜는 갱신되지 않았습니다.**
여러 사람이 같은 목록을 함께 보는 구조라, 누군가의 화면에서 목록이 다시 불러와질 때마다
"이 공사는 날짜가 옛날이니 하루 지났다"고 잘못 판단해 방금 저장한 체크를 되돌렸습니다.

→ 저장할 때 날짜도 함께 오늘로 찍도록 수정.
실제로는 v2.0(06시 체계 도입) 때부터 잠재해 있던 구조적 문제였습니다.

**사례 2 — 즐겨찾기가 앱을 켤 때마다 풀리던 문제 (v2.24a에서 수정)**

"없어진 공사의 즐겨찾기를 자동으로 정리"하는 기능이, 서버에서 목록을 받아오기
**전에도** 실행되었습니다. 그 순간 목록이 비어 있으니 "즐겨찾기한 공사가 전부
사라졌다"고 오판해 지워버렸습니다.

→ 목록을 다 받아온 뒤에만 정리가 돌도록 3중 안전장치를 추가.

> **교훈**: 06시 사이클이나 자동 정리 로직을 건드릴 때는,
> **"목록을 아직 못 받아온 상태"** 와 **"방금 저장한 직후"** 두 순간을
> 반드시 함께 검증해야 합니다.

# 6. 시스템 구조

## 6-1. 전체 그림

```
     [감독자 휴대폰]  ← 인터넷 주소만 열면 됨
            │
            ▼
   ┌────────────────────┐
   │  Cloudflare Pages  │  앱 화면을 배달하는 곳 (무료, 무제한)
   │  pocketboardprov2  │
   └────────────────────┘
            │
            ├──────────► [Supabase]  공사 기록·연락처·공지 저장
            │
            ├──────────► [구글 앱스스크립트] ─► 구글시트 자동백업
            │
            └──────────► [기상청 오픈API]  기온·습도·특보
```

## 6-2. 구성 요소별 역할

| 요소 | 하는 일 | 비고 |
|---|---|---|
| **Cloudflare Pages** | 앱 화면 배달 | GitHub에 올리면 자동 배포. 대역폭 무제한 |
| **Supabase** | 공사 기록·감독자 연락처·공지 저장 | 무료 요금제 |
| **구글 앱스스크립트** | 매일 06시 자동 백업, 체감온도 기록 | 실장 구글 계정 소유 |
| **기상청 오픈API** | 실황 기온·습도, 기상특보 | 울산 양정동 (격자 103, 84) |
| **GitHub** | 소스코드 보관·이력 관리 | 비공개 저장소 |

## 6-3. 파일 구성

| 폴더 | 내용 | 웹 공개 |
|---|---|---|
| `public/` | index.html, config.js, data.js, storage.js, manifest.json, 아이콘 | ✅ 이 폴더만 배포 |
| `server/` | Supabase SQL 파일, 앱스스크립트 파일 | ❌ 비공개 |
| `docs/` | README, 백서, 변경이력, 백로그 | ❌ 비공개 |

> ⚠️ **중요**: 새 파일을 추가할 때 **웹에 공개돼도 되는 것만 `public/`에** 넣습니다.
> 과거에 감독자 연락처가 담긴 SQL 파일이 웹 주소로 접근 가능했던 사고가 있었고,
> 그때 이 3분할 구조가 만들어졌습니다 (2026-07-26 보안 조치).

## 6-4. 기술적 특징

- **단일 파일 구조** — 앱의 거의 모든 기능이 `index.html` 한 파일에 들어 있습니다.
  별도 빌드 과정이 없어 수정·배포가 매우 빠릅니다. (현재 약 3,400줄)
- **감독자 명단·공장 정보는 `data.js`로 분리** — 명단만 고쳐 올리면 되므로
  본체를 건드리지 않고 인사 변동에 대응할 수 있습니다.
- **캐시 1시간** — 배포 후 최대 1시간 내 전원에게 자동 반영, 새로고침하면 즉시.

| 1 | **구버전 데이터 호환 필수** | 이미 저장된 기록이 새 코드에서 깨지면 안 됨 |
| 2 | **런타임 모호함은 안전한 쪽으로** | 조회 실패 시 "잘못된 것 표시"보다 "기존 값 유지" |

# 9. 앞으로의 계획

## 9-1. 다음 착수 예정

### 오프라인 지원 (착수 대기)

지금은 인터넷이 끊기면 **화면조차 뜨지 않습니다.** 공장 지하나 밀폐 공간처럼
신호가 약한 곳에서 치명적입니다.

**목표** — 오프라인에서도 온라인과 똑같이 입력하고, 인터넷이 돌아오면 자동 전송

| 온라인 때 | 오프라인에서 |
|---|---|
| 목록 조회 | 마지막으로 받아둔 목록 그대로 표시 |
| 점검 입력 | **완전히 동일하게** 입력 가능 |
| 저장 | 기기에 저장 + "오프라인 저장됨" 표시 |
| — | 인터넷 복귀 시 **자동으로 순서대로 전송** |

**핵심 전제**: 공사 1개는 감독자 1명이 항상 전담하므로, 여러 사람의 기록이 충돌해
합쳐야 하는 상황이 없습니다. 따라서 복잡한 병합 처리가 필요 없고, 순서대로
다시 보내주기만 하면 됩니다.

**제약**: `public/sw.js`라는 **새 파일이 반드시 필요**합니다.
브라우저 규격상 index.html 안에 숨겨 넣을 수 없어(보안상 금지), 컴퓨터 작업이
가능할 때 착수하기로 했습니다.

### 사진 촬영 + 구글 드라이브 백업 (v2.26 예정, 사양 확정)

- **권한**: 관리자(레벨1) 이상
- **방식**: 공사 세부 화면에서 카메라 즉석 촬영만 (갤러리 선택 불가)
- **저장**: 실장 구글 드라이브에 **공장별 폴더** 자동 생성
  ```
  1공장/  → OO공사_20260802_1.jpg
  2공장/  → XX공사_20260802_1.jpg
  ```
- **파일명**: `공사명_촬영일자_순번`
- **순번 중복 방지**: 여러 감독자가 같은 날 같은 공사를 찍어도 겹치지 않도록,
  서버가 저장 직전 기존 파일을 확인해 다음 번호를 매김
- **열람**: 폴더 주인(실장)은 전체 열람, 감독자끼리는 서로 못 봄
- **장수 제한 없음** — 10장 넘으면 안내 문구만 표시 (차단 아님)
- **착수 전 필요**: 앱스스크립트 수정 후 실장이 직접 재배포

> **분기 아이디어** — 드라이브에 쌓인 사진을 **구글 슬라이드로 자동 정리**
> (사진 1장 = 슬라이드 1장). 생성 시점·묶음 단위 등 미확정.
