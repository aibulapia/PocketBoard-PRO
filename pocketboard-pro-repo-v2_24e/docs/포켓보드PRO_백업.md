## 🔒 전역 지침 (영구 적용 — 항상 준수)

1. 판단이 안 서거나 궁금한 것이 있으면 먼저 물어볼 것
2. 더 좋은 제안이 있으면 3가지 이상 옵션을 제시하고 선택권을 줄 것
3. 출처가 불분명하거나 애매한 경우 별도로 표기할 것
4. 기존과 다른 수정사항이 발생하면 반드시 확인 후 진행할 것
5. **수정 요청은 "코드 작성" 명령 전까지 실제 코드에 반영하지 않고 대기 목록에만 쌓아둘 것**
6. **"코드 작성" 지시가 없으면 컴파일/빌드/패키징하지 말 것**
7. **코드 작성 전 대기 목록 전체를 다시 검토할 것** ("검토 한번 쭈욱")

## 🔑 인증 정보 (중요 — v2.10부터 2단계 권한)

> 암호는 앱 소스에 **SHA-256 해시로만** 존재. 마스터코드는 **서버(Supabase RPC)에서만** 검증(뷰소스 노출 없음).

| 용도 | 값 | 저장/검증 |
|------|-----|----------|
| 데이터 초기화 | (별도 보관 — 저장소에 기록하지 않음) | SHA-256 `5932cb6e…` (소스) |
| 회사명 수정 | `(별도 보관 — 저장소에 기록하지 않음)` | SHA-256 `9b8b07c4…` (소스) |
| **관리자 레벨1 (일반)** | `(별도 보관 — 저장소에 기록하지 않음)` | 서버 RPC — 공지 입력·연락처 조회/추가/전화. 삭제·세션등록소 숨김 |
| **관리자 레벨2 (최고)** | `(별도 보관 — 저장소에 기록하지 않음)` | 서버 RPC — 전체 기능 |
| 백업 토큰 | `(별도 보관 — 저장소에 기록하지 않음)` | Apps Script 전용 (기계, 사람입력 X) |

### 권한 시스템 상세 (v2.10 신설)
```sql
master_check(p_code)        -- p_code in ('(별도 보관 — 저장소에 기록하지 않음)','(별도 보관 — 저장소에 기록하지 않음)')
master_level(p_code)        -- (별도 보관 — 저장소에 기록하지 않음)→2, mmeec→1, 그외→0
master_guard(p_code)        -- 레벨1+ 통과 (공지/연락처추가)
master_guard_admin(p_code)  -- 레벨2만 통과 (연락처삭제/세션등록소)
```
- **상위 전용 RPC**: `master_upsert_session`, `master_delete_session`, `master_delete_contact`
- **공용 RPC(레벨1+)**: `master_set_notice`, `master_upsert_contact`, `master_list_contacts`, `master_list_sessions`
- 앱 localStorage `MMEEC_ADMIN_LV`에 레벨(1/2) 30일 캐시. UI 4곳(전체엑셀/세션등록소/연락처삭제/상태배지)에서 `masterLevel>=2` 조건부 렌더.

## ⚙️ 핵심 동작 메커니즘

- **06시 일일체계**: 하루 = 06:00~익일 05:59. 06시에 상태(공사중→재확인)·연장·TODAY 리셋, `pastWorkDays` 확정, **종료일 지난 카드 완전제거**.
- **TODAY 배지 (v2.11 변경)**: **오늘(workday 요일) 인원 배정된 공사만** 표시 (`hasWorkToday`). 기본 회색, 터치→파랑. n일째 표시.
- **안전보고문**: 공사전=당일 첫 기록, 공사중=12~14시 기록. 미측정시 경고팝업. 폭염대책+연장 포함.
- **관리자 인증**: 마스터코드(mmeec/(별도 보관 — 저장소에 기록하지 않음)) 서버검증→레벨 반환→localStorage 30일 인증+레벨+연락처 캐시.
- **공사기간 자동제거 (v2.11 버그수정)**: 엑셀 로딩 시 `dateWorkers`의 각 day를 **실제 날짜로 환산 후 가장 늦은 날짜**를 `endDate`로 계산 (day가 업로드일보다 15일 이상 작으면 익월 간주). **구버전 "최대 day 숫자=종료일" 방식은 월걸침(7/31~8/9 등)에서 7월31일을 8월9일보다 늦다고 오판 → 조기삭제 버그였음. v2.11에서 실제 날짜 비교로 수정 완료 및 검증됨.**
- **공지사항**: `app_notice` 단일행. 앱 시작 시 조회 → `updated_at`이 `MMEEC_NOTICE_SEEN`과 다르면 자동팝업. 수정=재표시.
- **TODAY 날짜배지 (v2.12)**: 라벨줄("터치 시 기록/편집" 옆)에 **"TODAY M/D(요일)"** 파란 배지 항상 표시 (실제 달력 날짜, 06시workday 아님). "공사목록(X건)" 표시는 삭제 (공장탭에 건수 이미 있어 중복).
- **탭 공사중 카운트 (v2.12)**: 공장탭 숫자를 공사전/전체 → **공사중/전체**로 변경. 공사중 = `status==="checked"` && (17시전 이거나 17시후라도 연장중). 공사전·종료(17시후+연장없음)는 제외.

- **TODAY 날짜배지**: "TODAY 7/22(수)" 정확 렌더, 공사목록건수 라벨 삭제 확인

## 🔲 백로그 (착수 대기)

### 세션 구조 재설계 (팀/현장별 공유)
**목적**: 공사목록은 관리자가 1벌 올려 전체 공유, 진행상황(상태·체감온도·TODAY·연장·메모 전부)만 팀 코드별로 분리

**확정된 사양**
| 항목 | 확정 |
|------|------|
| 공사코드 구분 기준 | 팀/현장별 (여러 팀이 같은 목록을 각자 진행) |
| 공통목록 업로드 | 관리자가 기존 방식 그대로 (초기화 후 파일변경으로 엑셀 업로드) → 전체 공유 |
| 새 엑셀 올리면 | 모든 팀 진행상황 초기화 |
| 진행상황 분리 범위 | 전체 (상태/체감온도/TODAY/연장/메모) |

**미확정**: 기존 default 데이터 마이그레이션 여부, 구현 방안(pocket_sessions 재활용 유력)

**착수 조건**: 실제로 여러 팀이 각자 공사코드로 나눠 쓰게 될 때. **현재는 `default` 세션 하나만 사용 중이며 문제없음.**
