## 확정 백로그 (9건)

### 1. 안전보고문 폭염작업 대책 자동 작성
- 공사전 복사: 그날 **최초 기록** 체감온도 사용
- 공사중 복사: **12시~14시 사이 최초 기록** 체감온도 사용
- 표기: 측정 시간 제외, 온도만 **소수점 첫째자리**까지
- 바텀시트 체감온도 표시도 소수점 첫째자리로 통일
- 해당 시간대 측정 기록 없으면 → **경고 팝업**, 복사 중단
- 체감온도 31℃ 이하(관심 미만)여도 대책 문구 **항상 작성**
- 단계별 대책 문구는 기존 heatIndex.levels guide 재사용

### 2. 기상 정보 팝업
- 위치: 울산 북구 양정동 (nx=103, ny=84 — 근사 계산치, 기상청 공식 엑셀로 대조 권장)
- 표시: 기상특보 요약(1~2단어) + 기상속보 배지(탭하면 전문 팝업) + 현재 기온 + 습도
- 갱신: 2시간마다 자동 (캐시 방식), 마지막 업데이트 시각 표시
- UI: 별도 팝업 (트리거 버튼 추가)
- API 준비 상태:
  - 단기예보(VilageFcstInfoService_2.0): 인증키 발급 완료
  - 기상특보 조회서비스(XML/JSON): 신청 완료
  - 기상속보용 TEXT API(통보문/특보 조회): 추후 필요 시 추가 신청
- 특보 코드 → 축약 라벨 매핑표 필요, 특보 없으면 "특보 없음"
- API 실패 시 마지막 캐시값 유지 + 갱신 실패 표시

### 3. 카톡 인앱브라우저 우회 + 홈화면 설치 안내
- 카톡 인앱 감지(User-Agent) → 기본 브라우저로 자동 이동 시도
  - Android: kakaotalk://web/openExternal 또는 intent:// 스킴
  - iOS: 제약 큼 → "다른 브라우저로 열기" 안내 버튼 폴백
- 진입 후 최초 방문이면 홈화면 추가(PWA 설치) 안내 팝업
  - Android: 설치 버튼 원클릭 / iOS: 공유→홈화면 추가 단계 안내
- localStorage로 안내 1회 표시 제한

### 4. 마스터 코드 (관리자 모드)
- 세션코드 기반 유지 (검토항목 A 보류 결정에 따름)
- 기능: 전체 세션 조회 + 수정 + 세션 등록소(registry) 관리(추가/삭제)
- 신규 테이블: session_registry (세션코드, 현장명, 등록일, 활성여부)
- 마스터 코드는 1895 수준이 아닌 강한 보호 필요
- **연락처 관리 (추가 확정, 추후 별도 진행 가능)**:
  - 감독자 연락처는 Supabase 서버에만 보관 (data.js/클라이언트 파일 절대 금지)
  - 마스터 코드를 서버측(RPC)에서 검증 후에만 연락처 전송
  - 일반 사용자 기기에는 연락처 데이터 자체가 미전송
  - 규모: 4번 본체 + 2~3일

### 5. 엑셀 저장 버튼 + 구글시트 자동 기록
- 수동 다운로드 (SheetJS 재사용, 신규 의존성 불필요):
  - **일반 세션코드**: 본인 현장 데이터만 다운로드 (전체 목록 접근 불가)
  - **마스터 코드**: 전체 현장 통합 다운로드
- 자동 기록: **B방식 확정** — Apps Script 시간 기반 트리거
  - **매일 00시(자정) 1회**, 직전 하루 진행기록 전체 저장
  - Apps Script가 Supabase REST 직접 호출 (앱 실행 여부 무관)
  - 대상: 4번 session_registry 등록 세션 전체 순회
  - 시트 탭 구성은 마스터 통합 기준, 현장별 구분
- 담을 컬럼: 공장/사업장/공사명/등급/작업/위치/감독자/인원(직영·일용·협력)/메모/체감온도이력/상태

### 6. 작업연장 버튼
- 카드 상세에 신규 추가
- 입력: 종료 시각, **1시간 단위** 선택, **24시간제**
- 자정 넘김: 00~23 리셋, 2자리 (예: "01시연장")
- 사유 입력 불필요
- 기본 종료시간 17:00 — 평소 화면 비노출, 연장 입력 시에만 표시
- 표기 형식 **"OO시연장"으로 전체 통일** (목록 배지/카드 상세/카톡 복사/안전보고문)
- 목록 화면: 17시 이후 **"공사중" 배지 자리** 교체
  - 연장 없음 → "종료"
  - 연장 있음 → "22시연장" (TODAY 배지는 유지)

### 7. TODAY 배지 터치 토글
- TODAY 배지 자체를 터치해서 상태 전환
- 파란 배경/흰 글씨(자동판정) ↔ **회색 배경/이탤릭**(수동 취소)
- 텍스트 "TODAY" 그대로 유지
- 자정 지나면 자동 리셋 (다음날 자동판정으로 복귀)
- 재터치로 원상복귀 가능

### 8. TODAY "n일째" 표시
- 공사가 여러 날 진행 중이면 TODAY 옆에 "2일째" 등 표시
- 1일째는 생략, 2일째부터 표시
- 미확정: 시작일 기준 (A: 엑셀 날짜 컬럼 최초 등장일 / B: 앱 최초 인식일 자동기록)
- 미확정: 7번 수동취소일도 카운트에 포함할지

### 9. 감독자·공장 데이터 외부화 — B-1만 확정
- index.html 내 감독자 명단/공장 목록/작업유형 코드를 별도 `data.js`로 분리
- 규모: 반나절
- **원칙: 이름만. 연락처·사번 등 개인정보는 data.js 절대 금지** (연락처는 4번의 서버 보관 방식)
- B-2(Supabase 테이블화)는 보류 — 명단 변경이 잦아지면 재검토
